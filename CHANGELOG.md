# Changelog

## Unreleased

- Discover: read what the target declares about itself, and the JavaScript it ships. Every run now fetches the well-known documents at the origin — `sitemap_index.xml` alongside `robots.txt`/`sitemap.xml`, plus the `.well-known/` registry (`openid-configuration`, `oauth-authorization-server`, `oauth-protected-resource`, `security.txt`, `apple-app-site-association`, `assetlinks.json`, `host-meta`, `change-password`) — and crawls the endpoints they name; one OIDC discovery document hands over authorize, token, userinfo, JWKS, revocation and registration. `.well-known` was already a wordlist entry, which is not the same thing: that probes it once per calibrated *directory*, never at the origin on a path-confined run, and reads nothing it says. A response that is neither HTML nor a sitemap used to yield NOTHING, so the spider followed `<script src>`, spent a real request on the bundle, decoded and fingerprinted it, and then discarded every route in it — on anything SPA-shaped that is the whole application, since an API route reachable only from JS is by construction unlinked and therefore absent from the wordlist too. Bundles, JSON, source maps and inline `<script>` are now read for endpoints, filtered on the quote that separates `fetch("/api/v2/cart")` from a regex literal or a MIME type. Measured against a local origin: 3 findings became 10
- Discover: a soft-404 baseline is a snapshot, and a target that changes its mind mid-sweep used to be reported as several hundred discoveries. A baseline is measured once per directory and never revisited, so when an origin's rate limiter tripped on the 8th request every remaining probe diverged from it in status *and* length *and* content — a run against one ended `320 found`, of which 310 were the limiter, each at confidence 1.0. A `429`/`503` guard is not the answer, because the new uniform response is as often a 200 block page or a 403: Discover now watches for a run of probes that all clear the baseline *and* all look identical, holds those results back instead of reporting them, and re-measures the directory. What it drops is reported as `drift` in the run summary, so a directory that went unmeasured never reads as one that was empty
- Discover: report a real page on a 200-everything origin instead of dropping it. A wildcard-200 hit needed the content to diverge *and* the length to fall outside a band of 5% of the page, so a real page sharing the error page's template — which is what a CMS or SPA soft-404 always is — was suppressed however different its content: a 524-byte `/soft/admin` sat inside a `[518, 572]` band and was never reported. Content alone is now enough, *unless* the origin quotes the requested path back into its miss page, where content divergence is the echo rather than the endpoint. That is measured rather than assumed, and it has to be measured directly: the fingerprint skips long hex runs so that ids and hashes cannot move it, and the bogus probe names are 16 hex characters, which makes a reflected name invisible to the very hash it would show up in. Each calibration probe now looks for its own name in its own body, at no extra request, and the run says which of the two it found (`wildcard-200 (echoes path)`)
- JWT: the lens switch says so on screen. Each lens is a complete workbench, so nothing inside one showed that the other existed — `Ctrl-T` was named in Help and in the status footer and nowhere on the panes. The top card of each lens now carries the switch on its border, naming where the key GOES (` ^T:→ENCODE ` on INPUT, ` ^T:→DECODE ` on HEADER), and a click on the chip flips the lens like the chord. The chip resolves through the keymap, so a rebound switch renames it and the footer beside it. Pressing a chip no longer arms a text gesture either: the press flips the lens, and the drag or double-click that follows used to land in the pane the flip had just revealed and open a selection there. The guide stops naming `Ctrl-E`, which stopped switching lenses when the key moved off the shell's reserved external-editor chord, and its screenshot is a fresh capture — the old one predates both this chip and the `NOR` → `READ` rename
- `gori ca`: a flag written before the verb no longer swallows it. `gori ca --ca-dir=DIR regenerate` printed the CA path and exited 0 having regenerated nothing — output identical to a successful `gori ca`, so the destructive command read as done. Both verbs now insist on coming first, and a stray word is a usage error on all three forms instead of being ignored (`gori ca regenerate --yes bogusword` used to rotate the CA and say nothing about the word)
- `gori ca regenerate` / `gori ca import`: work on a CA directory where only one of `root.crt.pem` / `root.key.pem` survives — a partial restore, an accidental `rm`. Both went through the loader, which refuses that state and tells the operator to "run `gori ca regenerate`", so the advertised repair was blocked by the very check advertising it and no non-manual way out existed. Neither command needs the old pair, and neither asks for one now; a fresh directory also stops minting a throwaway gori root just to overwrite it on import
- `gori ca import`: reject an Ed25519 or Ed448 root instead of adopting it. Such a pair passed both checks (key matches cert, cert is a CA), was persisted, and then failed to sign at the first CONNECT — every interception broken by an import that reported success. Validation now mints a throwaway leaf to prove gori can sign with the key at all. `gori ca` also names an already-installed unusable root, including a key that does not match its certificate, which nothing reported before: that failure surfaces only at the client, as "unknown CA" or "bad signature". The check runs on every `gori ca`, `--pem` included, and reports on stderr only — stdout stays exactly the path or the PEM, so pipelines are unaffected
- `gori ca import`: say what is wrong with a `--cert` / `--key` path in the operator's terms — not found, a directory, unreadable, not PEM — instead of naming the OpenSSL call that failed (`BIO_new_file(nope.pem) failed`, or "PEM_read_bio_X509 failed" for a directory, which opens fine). The TUI's **Import CA certificate** overlay inherits the same messages
- TUI: pasting into the Repeater's REQUEST pane no longer freezes the app. The bracketed-paste end marker (`\e[201~`) was never matched on the pinned termisu — its probe skipped the input fd whenever the poll budget was spent, and the budget is always 0 on the drain termisu's own input source uses — so `PasteEnd` never arrived, the paste never landed, and every keystroke after it was swallowed into a bulk insert that was never flushed, with the frame still repainting. Carried as a patch here (`tui/paste_end_marker_patch.cr`), guarded by a behavioural spec, and deletable the moment `shard.lock` moves. Only `main` was ever affected, never a release: v0.2.0 predates bracketed paste entirely
- TUI: a paste the terminal cuts short no longer poisons every later paste. The parser had no way out of paste mode once a paste was truncated, so the NEXT paste's start marker was read as an end marker, missed, and answered with an Escape — which dropped the request editor out of INSERT and ran the rest of the clipboard as commands, navigating tabs by the digits in `HTTP/1.1`
- TUI: a lost paste end marker can no longer present as a dead keyboard, whatever the cause — a terminal killed mid-transfer, a dropped ssh session, DEC 2004 switched off underneath. A paste arrives as a burst while typing does not, so input going quiet while a paste is open now ends it, delivers what arrived, and says so
- Comparer: read the diff instead of scanning it. A changed row now lights only the runs that actually differ (a re-signed token, one flipped JSON value) and dims what both sides share; `n` / `⇧N` jump between changed rows and the footer says which one you are on; `f` folds the identical runs to `⋯ N unchanged lines ⋯`, so a 900-line response whose diff is three lines fits on one screen
- Comparer: each column header carries that side's `status · size · time`, and the divider between them states the A→B delta — a `403 → 200`, `+16 B`, `+371 ms` — which is the whole answer to most comparisons, before a body line is read
- Comparer: fill a slot from anywhere that holds a request and a response, not just a captured flow — `Space` → **Send to Comparer** now exists on the Repeater (its last send), the Sitemap, and Fuzzer result rows. A Repeater send and a fuzz row leave no capture behind, so this is the only route those two ever had into a diff
- CLI/MCP parity: `gori run compare --context=N` and `compare_flows context:N` fold the unchanged runs the same way the tab does (`@@ N unchanged lines @@` / `{kind:fold,hidden}`), and both surfaces now report each side's status/size/duration plus the delta. `--changes-only` says *what* changed but erases *where*; `--context` keeps the change in place
- `gori run`: a `--` separator no longer switches a subcommand's argument handling off. Every `gori run` verb read only the first of the two lists `OptionParser` hands back, so everything past a `--` was silently discarded: `gori run decoder base64-encode -- hello` dropped the input and read STDIN instead, printing nothing at exit 0, and `gori run links add … -- junk` sailed past the guard that exists to refuse stray positionals. Same defect `gori settings` was fixed for, in the sixty sites that had copied the idiom from each other; a spec over the source now fails if a new subcommand reintroduces it
- Probe: the AFFECTED URLS list in a finding's detail is navigable — `↵` (or `l`/`→`) opens the flow the highlighted URL was captured on in History, the gesture the Issues detail's related-links list has always had. `o` still opens the finding's one sample flow, so up to 49 of a 50-URL group used to be dead rows in the pane that listed them
- Discover: a page linked from a well-known document is a link, not a guess. The `well-known` source is what routes a finding through the origin's soft-404 baseline instead of trusting its status, which is right for the documents gori guesses at and for the endpoints they declare — but it was inherited by every page below them, with no depth limit, so an ordinary `<a href>` two hops down was judged against the *seed origin root's* miss page. On an origin that answers `401` to unknown paths that erases exactly the finding worth having: a linked page returning 401 diverged from the baseline in nothing and was dropped, while the identical page reached from `/` was reported. The source now stops at the document's own links
- Colormarker: a global rule painted with a custom colour keeps it. `colormarker.colors` names were rewritten to `yellow` every time settings.json was read, because the global-rule parser clamped `color` to the six built-in words — and since the next save re-serialises what is in memory, the rule lost its colour permanently at the first restart. Project-scope rules were never affected. An unknown colour is now kept as written and resolved at render, which is where a dangling reference already fell back to a visible default
- OAST: a poll that fails partway no longer discards what it already collected. PostBin is drained by destructive shifts, so a transport failure on the fifth shift threw away the four interactions the bin had already handed over and no longer held — the same evidence loss a malformed *body* was guarded against, one call up. The batch is kept and the remainder drains next cycle; a cycle that collected nothing still reports the failure, so an unreachable provider is never silent
- Discover: bound what one response can spend. An un-quoted `http://` in a minified bundle could match up to the whole 2 MiB scan window as a single "URL" and carry that string through resolve/parse/dedup, and a page could exceed the per-body link cap by arriving through more than one extraction pass
- Discover: reading a JavaScript bundle no longer buys a brute-force sweep of every directory it mentions. A crawled link seeds a wordlist sweep of its whole directory — ~315 sends before extensions — and that was spent the moment a link was *considered*, without waiting to see whether it resolved. That was defensible while links were authored `<a href>`s; now that the endpoint pass recovers them from quoted strings in text, a bundle's i18n namespaces, asset chunks and vendor paths each bought a sweep of a directory that does not exist. Measured against a live origin, a bundle of 120 such literals turned one response into 38,929 requests for 2 findings. A link the target DECLARED (an attribute, a `<meta refresh>`, a robots.txt value, a sitemap `<loc>`) still seeds its directory immediately, so a robots entry naming a file that is gone still gets its directory swept; an inferred literal seeds its directory once its own fetch says something is there — 401 and 403 included, since an endpoint behind auth is the strongest reason to look at its neighbours. The same origin now spends 769 requests, and a real SPA whose bundle names routes that answer is byte for byte unchanged at 4,561
- Discover: a brute-force candidate is derived by string concatenation as a fast path, and it is only ever allowed to agree with the full parse it replaces. It disagreed on trailing Unicode whitespace: `URI.parse` right-strips a path with the Unicode `Char#whitespace?`, so a wordlist entry ending in U+00A0 or U+3000 came back one character shorter from the parse and unchanged from the concatenation — one entry, two different URLs requested, and copy-pasted or HTML-scraped wordlists carry trailing NBSP routinely. The fast path now declines anything outside ASCII and lets the parse answer; the whole built-in wordlist is unaffected
- Colormarker: editing a rule no longer rewrites a colour the picker cannot offer. Deleting a custom colour deliberately leaves the rules that name it alone — they keep the reference and fall back to a visible default, so re-adding the colour restores them — but the rule editor showed the first built-in (`red`) for a colour it did not recognise, so saving that rule after changing only its name or its condition wrote `red` to the store. The form now offers the colour the rule arrived with
- Rewriter: moving a rule between the global library and the project can no longer leave it in both. The copy is written to the destination before the original is dropped, but a source store that then refused the delete left the rule in both scopes — applied twice on every matching message — while the status line said it was unchanged. The copy is now undone when the move cannot complete. Relatedly, a global delete that fails to reach settings.json no longer clears this project's override for it, which had silently switched a rule the operator turned off here back on

## v0.2.0

- Proxy: upstream connection rules with per-host routing, SOCKS5 and proxy auth; a TLS pass-through list that is never MITM'd; per-destination outbound TLS (client certificates, protocol floor, ciphers); a setting to force HTTP/1.1; transparent listeners and additional listeners alongside the primary bind (#434, #435, #436, #437, #438)
- Proxy: harden the HTTP/2 assembler against CONTINUATION spoofing and stream-slot exhaustion, re-sync framing after a head rewrite so Match&Replace can't smuggle, and reject bare-CR header obfuscation and ambiguous response framing (#341, #403, #409, #412, #417)
- Proxy: serve the CA-download page at a reserved host, `gori.proxy` (#347)
- TUI: multi-select in History, the Intercept queue, the Sitemap tree, and the Issues list, so the space menu acts on N items at once (#442, #459, #460, #461)
- TUI: the Project tab becomes sub-tabs instead of five tiled panes, Network settings gain upstream-rules and outbound-TLS tables, a Keys section picks the command modifier (⌥ reaches the shortcuts Ctrl can't), plus `rosepine` and `tokyonight_day` themes (#440, #454, #458, #462, #463)
- TUI: export the current note to Markdown from the Notes space menu, and ask where to write the Issues report instead of always overwriting `<project dir>/issues.{md,json}`. Export is `⇧E` on both tabs; the Issues list's old `x` is freed, so `x` now means "Select line" everywhere (#432)
- Settings: `--config PATH` plus settings export/import profiles, per-project connect/idle timeouts and capture limit, and a unified retention policy (#439, #440, #441, #448, #450, #455)
- Import: read Postman collections, Insomnia exports, and Burp XML (#453)
- Probe: active-scan rules for open redirect, CRLF/response-header injection, host-header injection, access-control bypass, NGINX-style parameter traversal, GraphQL introspection, SSTI, and Next.js server-action missing authorization; passive rules for JWT weaknesses, source maps, SRI, and directory listing; a manual unsafe-method opt-in and AGGRESSIVE mode (#299, #342, #343, #346, #349, #350, #451)
- CLI/MCP: bring `gori run` and `gori mcp` to TUI parity, and create/delete projects from `gori run project` (#351, #352)
- Performance: move trigram FTS indexing off the capture commit path, and reuse one HTTP/1.1 connection across a fuzz sweep (up to 20x on HTTPS) (#428, #433)
- Security: close request-splicing and scope-gate holes across Discover, Fuzzer, Repeater and Scope — crawled-link splicing, unvalidated redirect `Location`, per-URL probe authorization, fail-open scope, irregular request-line whitespace, and `wss://` targets dialing cleartext (#390-#397, #404-#407, #418-#422)
- Security: keep gori's own files owner-only — the CA private key is now 0600 from creation (it used to land at the umask default and get chmod'd a syscall later, and a key that got loose any other way was never re-tightened) and is re-asserted on every load, and a settings export carrying a secret is written 0600. `--config` and `--ca-dir` no longer re-mode a directory the operator merely named (#466, #467)
- Say what went wrong instead of swallowing it: a TUI session that can't open (a bad `--db`, an unreadable store) reports why on the project picker rather than dropping the operator on "no projects yet"; an unparseable `settings.json` says it is falling back to defaults rather than resetting the bind, upstream rules and TLS pass-through list in silence; and a path that should be a directory but isn't (`--ca-dir notes.txt`) is named as such instead of surfacing as `BIO_new_file(...) failed` or a raw backtrace
- Refactor: a single outbound chokepoint for the active-traffic scope gate, one Plan builder per engine (fuzz, discover, miner, repeater, sequencer) shared by TUI/CLI/MCP, and all 28 TUI modals on one Overlay seam (#354, #355, #356, #361)
- Packaging and docs: Nix flake with an update channel, `AGENTS.md`, `DESIGN.md` with the P0-P8 principles, and an install script that survives GitHub API rate limits (#338, #345, #353, #360, #429)
